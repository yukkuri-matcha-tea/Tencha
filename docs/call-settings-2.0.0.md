# 2.0.0 通話設定とバグ確認

## 実APKの根拠

LINE 26.15.1（261510192）のDEXから、組み込み・外部着信音、LINE標準・相手指定呼出音の各ファクトリーとURIモデルを確認。[宣言照合](call-tones-26.15.1-mappings.json)。既存のグループTTSの根拠は[前回の調査](call-settings-1.10.0.md)を参照。

`ps7.a$b$a.b(Context)`（標準）と`ps7.a$b$b.b(Context)`（OBSRemoteData）の両方で、自分側の呼出音を`a40.b(Uri)`へ差し替える。LINEの再生・ループ・通話開始時の停止処理を維持し、AudioTrackやマイクには触れない。標準への強制変更はリモート側だけで行うため、標準ファクトリーが自分自身を呼ぶ再帰は発生しない。

## 保存と優先順位

- 初期OFF。ファイルを選ぶだけではONにしない。
- 着信音は`files/tencha_ringtones`、呼出音は`files/tencha_ringbacks`へPCM16・16kHz WAVとして取り込む。選択元ファイルは変更しない。
- 自分が聞く呼出音だけを変更する。相手の設定・相手側で聞こえる音には影響しない。
- 有効なカスタム呼出音 → LINEデフォルト指定 → LINE本来の選択、の順で優先する。
- 未設定・ファイル消失時は純正へ戻す。音源実体は設定バックアップには含まれない。

## 発見して修正した問題

1. SettingsStoreのメモリー内キャッシュを保存成功と誤認していた。音源パスと表示名をローカルSharedPreferencesへ同期・原子的に保存してから以前の取り込みファイルを削除するよう修正。着信音と呼出音は独立したキー・ディレクトリーを使う。
2. 音声デコーダーが応答しない場合の待ち続けを防止。15秒間入出力の進捗がない場合に失敗として終了し、以前の音源を残す。曲の長さ自体を15秒に制限するものではない。
3. ホーム設定ボタン長押しが`kotlin.Unit.INSTANCE`を参照して失敗していた。26.15系の実DEXにある`ip8.i0.a`へ修正。通常タップは変更しない。

## 検証範囲

ユニットテスト43件（失敗0）でカスタム音の優先、未設定時のフォールバック、初期OFF、標準ファクトリーの再帰回避などを確認。DEX宣言照合は通話設定11/11項目、版対応50/50項目に成功。Android Lintはエラー0件・警告157件、APKビルドと署名検証に成功。

接続端末へ2.0.0を導入しLINEを再起動。ホームの設定長押しでモジュール設定を開けること、通話カテゴリと新しい呼出音設定の表示をUI階層・スクリーンショットで確認した。音源の取り込み・設定スイッチの変更は行っていない。

こちらから通話・メッセージ送信は行わないため、実際の着信・呼出音の再生と停止、TTSの相手への到達は未検証。静的チェックや起動確認を全機能の実機保証とは扱わない。
