# 1.10.0 通話設定

## APK根拠

LINE 26.15.1 base.apkのclasses4.dex / classes8.dexを解析した。参照した26.15.0のsmaliから検索候補を絞った後、26.15.1の宣言と実装を確認した。[宣言照合10項目](call-tones-26.15.1-mappings.json)。

- `ps7.a$a$a.d(Context)`は組み込み着信音のURIを`a40.b`へ渡す。`ps7.a$a$b.d(Context)`は外部着信音のURIを同じ型へ渡す。この2箇所だけを差し替え、上位の`ps7.a$a.b(Context)`が`qs7.c`でラップする処理は維持する。通話のAudioTrackやマイク処理は変更しない。
- 相手の呼び出し音は`ps7.a$b$b`（toString: OBSRemoteData）が`qs7.b`でリモート音源を再生する。設定ON時は、その`b(Context)`を標準音`ps7.a$b$a.a.b(Context)`へ置き換える。標準音は`it7.a.RINGBACK_1`を使用する。
- グループ通話の実セッションは`ew7.i`。`l`が`kw7.a`、`kw7.a.j`がConnectInfo。`VoIPGroupCallConnectInfoImpl.q()`はコンストラクターで受け取ったグループIDを返す。`kw7.a.k/A0()`は表示名であり、IDとして使用しない。JADXの自動getter別名ではなく、DEX宣言の`q`を使用する。
- LINEの受信メッセージのfrom/toフィールド、自己送信の`chat_history.chat_id`を使ってチャットを判定する。グループID未取得時はグループ限定TTSを許可しない。

## 設定と保存

通話カテゴリへ既存3機能を移動したが、保存キーは変えていない。TTSの従来の`all`は全チャットの意味で維持し、新規設定の初期値は`call_chat`。対象者の既存モードも維持する。

着信音は既存の音声デコーダーでPCM16 / 16kHz WAVへ変換し、LINEの`files/tencha_ringtones`に保存する。サウンドボードの登録リストには追加しない。新しい音源の変換が失敗しても以前の選択を維持する。再選択が成功した場合は旧取り込みファイルを削除する。元の選択ファイルは変更・削除しない。

設定バックアップのみから音声の実ファイルは復元されないため、ファイル未検出時は純正音へ戻る。音声ファイルの取り込みで自動的に着信音変更をONにはしない。

## 検証範囲

40件のユニットテスト、Android Lint、APKビルドを確認。チャット範囲の完全一致、別グループ・個人チャットの拒否、ID不明時の拒否、旧全員設定の互換をテストした。

接続端末へ1.10.0をインストールし、LINEを完全終了して再起動。モジュール設定の「通話」カテゴリ、既存のサウンドボード・TTS・独立ミュート、着信音変更とファイル選択、相手の呼び出し音無効化の表示をUI階層とスクリーンショットで確認した。TTS設定画面の新しい対象ラベルと、着信音ファイルのシステム選択画面を開くところまで確認した。こちらでは音源を選択・取り込みせず、ファイル選択をキャンセルした。

実際の着信、相手が設定した呼び出し音、グループ通話中のTTS音声到達は、こちらから通話・メッセージ送信を行わないため未検証。宣言照合とUI確認だけで実機の全挙動を保証しない。
